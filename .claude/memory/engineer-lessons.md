# engineer — lessons (terse, deduplicated, cap ~15 lines)

- 2026-07-14 (S0): walk-sim/spike declare NO `kotlin-test` dep — write core-osm/core-sim tests with JUnit Jupiter (`org.junit.jupiter.api`), matching neighbours; `assertEquals(expected,actual,msg)` arg-order matches kotlin.test. JUnit's generic `fail` → call `fail<Unit>(...)`.
- 2026-07-14 (S0): Gradle gotchas — env vars (e.g. WALKSIM_PERF) do NOT reach the forked test JVM through a WARM daemon → run perf with `--no-daemon`; a `--tests`-filtered run leaves `:<mod>:test` up-to-date so a later unfiltered `test` is SKIPPED → prove full-suite green with `--rerun-tasks` (confirm "N tasks executed", not up-to-date).
- 2026-07-14 (S0): golden `check()` reads `File("src/test/resources/golden/…")` from the SOURCE tree (not the classpath), so record-then-assert round-trips through source; Gradle test working dir = module root.
- 2026-07-15 (S1): package hoist (move A.X→B.X) breaks EVERY file that used `X` UNqualified in A's package, not just the spec-named ones — grep the OLD package dir for the bare symbol (`\bGeo\.`), not only FQN `a.X` (14 :core-sim + 4 :core-osm files needed repointing vs 2 named). Moving a test into a previously test-free module needs that module's build.gradle to add `testImplementation(libs.junit.jupiter)` + `tasks.test { useJUnitPlatform() }`.
- 2026-07-15 (planB-S0): Kotlin 2.0+ (here 2.1.0) DROPS legacy `composeOptions{ kotlinCompilerExtensionVersion }` / standalone `androidx.compose.compiler:compiler` (that path is Kotlin ≤1.9 only) — enable Compose by applying the `org.jetbrains.kotlin.plugin.compose` Gradle plugin at the SAME version as Kotlin (catalog: `version.ref="kotlin"`) + `buildFeatures{ compose=true }`, no composeOptions. BOM-managed compose libs get version-less catalog entries; `androidx-compose-ui` + `androidx-compose-ui-tooling(-preview)` coexist fine (dash→dot accessors don't collide). Compose BOM 2024.12.01 builds on compileSdk 34 (no bump). foundation (Column/Box/background) is transitive via material3 — no explicit dep.
- 2026-07-15 (planB-S1): Compose `setContent {}` is an extension on `androidx.activity.ComponentActivity`, NOT `android.app.Activity` — migrating an `Activity` host fails with "Unresolved reference / receiver type mismatch"; change the superclass (ComponentActivity still gives checkSelfPermission/startForegroundService + is the LifecycleOwner `collectAsStateWithLifecycle` needs). `collectAsStateWithLifecycle` + `lifecycle-runtime-compose` arrive transitively via `activity-compose` (compose BOM 2024.12.01) — no explicit dep. Verify transitive compile availability with `:app:dependencies --configuration debugCompileClasspath` (grep sans `(c)` = real resolution, not just a constraint).
- 2026-07-15 (S2): `:app`/spike unit tests have NO Robolectric → android framework is not mocked: `Uri.parse`/`MatrixCursor` throw "not mocked" (surfaces as `ExceptionInInitializerError` when a companion eagerly builds a `Uri`). Assert contracts against `const val` String seams (add `CURRENT_URI_STR`), make `Uri` fields `by lazy`, fake a `Cursor` via `java.lang.reflect.Proxy` (override only the reads used). Reading a `const val` skips `<clinit>`; calling a companion fun triggers it.
- 2026-07-15 (planB-S2): a cosmetic osmdroid `Polyline(mapView)` STEALS taps from a `MapEventsOverlay` (breaks tap-to-place): near the line `onSingleTapConfirmed`→`click()`, and with NO click listener `click()` returns `onClickDefault()` which returns TRUE unconditionally (`javap -c`-confirmed in 6.1.20). `infoWindow = null` does NOT fix it — `click()` branches on `mOnClickListener`, not the infowindow. FIX: `setOnClickListener { _, _, _ -> false }` so `click()` returns the listener's false → `DefaultOverlayManager` keeps iterating (top-first) → tap reaches the MapEventsOverlay. Host osmdroid in Compose via `remember { MapView }` + attach overlays in `AndroidView.factory` (runs once, no leak) + `DisposableEffect` wiring onResume/onPause/onDetach to `LocalLifecycleOwner` (from `androidx.lifecycle.compose`); guard `LocalInspectionMode.current` (early-return a Box) so @Preview/LayoutLib never instantiates a MapView.
- 2026-07-15 (planB-S5): adaptive launcher icon needs NO PNG density fallback when minSdk≥26 — a `mipmap-anydpi-v26/ic_launcher.xml` `<adaptive-icon>` (bg+fg+`<monochrome>`) alone builds+packages (aapt2 satisfied since every device is ≥v26). In-vector gradients need `xmlns:aapt` + `<aapt:attr name="android:fillColor"><gradient>` (extracted as `$name__0.xml` in the APK — expected). Splash: `androidx.core:core-splashscreen`, a `parent="Theme.SplashScreen"` theme with `windowSplashScreenBackground`/`windowSplashScreenAnimatedIcon`/`postSplashScreenTheme` (post-theme = old look for an unchanged app), that splash theme on the launcher `<activity>`, and `installSplashScreen()` BEFORE `super.onCreate`. Splash animated-icon vector = 288dp canvas, art within centre ~192dp (circle-mask safe).
- 2026-07-15 (planB-S3): two Compose codegen traps, both caught pre-commit. (1) Pure JVM-tested fns must NOT sit in a Compose-compiled file — loading it off-device throws `ClassFormatError: Illegal method name "<anonymous>"`; keep such seams in a Compose-free sibling `.kt`. (2) An early `return`/`return@key` inside a `@Composable inline` lambda (`key{}`, and by extension any inline composable-scope lambda) is a non-local return D8 CANNOT dex — `Method name '<anonymous>' in class '$$$$$NON_LOCAL_RETURN$$$$$'`; this breaks `assembleDebug` (dexBuilder), not just unit JVM. FIX: replace early returns with positive `if (…) { }` nesting. Diagnose dex failures with the D8 line from `--stacktrace` (grep it), not the generic "Failed to process kotlin-classes/debug". Animation deps (animation-core) are transitive via the Compose BOM — no new dep for animate*AsState/rememberInfiniteTransition/Animatable.
- 2026-08-11 (R2/R3): the street graph DROPS footway/path/steps/cycleway/track AND `OverpassGraph` keeps only the LARGEST component — so any foot-only place (Enoshima island, Haneda terminal decks) is silently deleted, surfacing as "no connected graph node within 200 m of start" or a waypoint missed by ~2 km, never as an error. Widen per-call (`graphAround(..., extraWalkable)`), never globally, or every existing preset's graph changes. Also: a fixed-waypoint route needs a CENTRAL start — an edge start puts far sites at the fetch-disc rim where their roads get clipped into a discarded component.
